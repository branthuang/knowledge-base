# hybrid-search Specification

## Overview
混合搜索系统是实现“先查自己的知识，再向 AI / 公网提问”核心原则的技术基石。系统提供全局统一搜索入口，通过“全文关键词检索 + 向量语义检索”双路召回，结合结构化条件过滤与加权融合排序，并根据充分性评估向用户精准推荐 AI 补充搜索。

## Requirements

### Requirement: 全局统一搜索入口
系统在首页工作台与顶部全局导航必须提供单一且明显的搜索输入框，无需用户事先区分本地检索还是 AI 问答。

#### Scenario: 统一入口接收查询
- **WHEN** 用户在全局搜索框输入自然语言问题或业务关键词并回车
- **THEN** 系统立即启动本地知识库多路混合检索流程并跳转到统一搜索结果页。

### Requirement: 多路召回引擎（关键词 + 向量）
搜索后端必须同时执行基于文本关键词的全文检索（FTS）以及基于向量相似度的语义检索（pgvector）。

#### Scenario: 关键词与语义双路并发查询
- **WHEN** 系统接收到检索 Query
- **THEN** 系统执行：
  1. 全文检索（关键词召回）：对标题、摘要、标签及派生正文文本进行分词匹配，标题赋予最高召回权重；
  2. 语义检索（向量召回）：生成 Query 的向量 Embedding，在向量表中检索余弦相似度最高的内容块/知识点。

### Requirement: 多维结构化过滤
搜索必须支持与结构化属性的交集联合过滤。

#### Scenario: 组合过滤条件查询
- **WHEN** 用户指定了分类（支持父分类级联）、一个或多个标签、来源类型（如 `ai_search`）、更新时间区间或收藏状态
- **THEN** 系统在多路召回前或召回融合过程中严格过滤不满足条件的知识记录。

### Requirement: 混合加权融合排序与结果聚合
系统必须将关键词匹配分与向量语义分进行归一化加权融合，且在知识点维度聚合并高亮最优片段。

#### Scenario: 分数融合与分块聚合
- **WHEN** 多路检索返回多个匹配的文本分块（chunks）
- **THEN** 系统将分数融合（关键词分 + 语义分 + 标题命中加权 + 时间衰减因子），按知识点（`knowledge_id`）聚合去重，并提取最相关的正文摘要片段进行关键词高亮。

### Requirement: 本地知识充分性判定
系统不得仅以“返回数量为 0”作为未命中标准，必须通过相关度分数阈值综合判断本地知识是否足够覆盖用户查询。

#### Scenario: 判定为本地知识不足
- **WHEN** 检索结果中前 Top 5 项的最高综合得分低于系统设定的 `minimum_score` 阈值，或满足阈值的有效结果数量为 0
- **THEN** 搜索结果页明确提示“本地知识库中未找到足够匹配的内容”，并在结果下方展示明显的“继续使用 AI 搜索”行动按钮。

#### Scenario: 判定为本地知识充足
- **WHEN** 检索结果中存在得分高于 `minimum_score` 的高相关度知识
- **THEN** 搜索结果页优先展示匹配的知识卡片，并允许用户直接点击预览或进入完整知识详情，同时在页面右侧或底部保留折叠式的“向 AI 提问”备用入口。
