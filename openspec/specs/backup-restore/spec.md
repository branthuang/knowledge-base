# backup-restore Specification

## Overview
数据安全、备份与恢复模块确保个人知识库资产的绝对主权与灾难恢复能力。遵循“业务数据库为权威事实、搜索索引为派生数据”的核心架构准则，支持完整数据包导入导出与一键全量重建索引。

## Requirements

### Requirement: 完整备份包一键导出
系统必须支持将个人知识资产的结构化数据、附件文件及元数据完整打包导出。

#### Scenario: 生成全量备份包
- **WHEN** 用户在设置中点击“导出完整备份”
- **THEN** 系统生成包含以下内容的 ZIP 归档压缩包：
  1. 结构化业务数据快照（JSON / SQL dump 包含知识、分类、标签、来源等）；
  2. 关联的多媒体静态资源文件（`assets/` 目录）；
  3. `manifest.json` 元数据文件（包含导出时间、应用版本号、数据校验和 checksum、统计摘要）。

### Requirement: 完整备份包恢复与完整性校验
系统必须支持从标准全量备份包中恢复数据，并在写入前执行版本与校验和检查。

#### Scenario: 执行数据恢复
- **WHEN** 用户在空环境或指定系统中上传合法的备份 ZIP 包并确认恢复
- **THEN** 系统先校验 `manifest.json` 的版本兼容性与文件哈希；校验通过后，原子性导入数据库记录，解压静态附件至存储目录，并自动触发全量派生索引构建。

### Requirement: 单篇知识独立导出
系统必须支持将单篇知识内容无损导出为通用开放格式。

#### Scenario: 导出 Markdown 或 HTML
- **WHEN** 用户在某篇知识详情页选择“导出为 Markdown”或“导出为 HTML”
- **THEN** 系统将结构化 blocks 递归转换为对应排版语法的文本文件，包含标题、正文及引用来源，支持直接下载到本地。

### Requirement: 派生索引全量重建
当全文搜索引擎或向量数据库出现损坏、重置或参数调优时，系统必须支持完全依赖数据库正文一键重新生成所有索引。

#### Scenario: 触发索引全量重建
- **WHEN** 用户在系统设置页面点击“全量重建搜索与向量索引”
- **THEN** 系统清空当前派生索引表，遍历所有非回收站状态的 `knowledge_items`，重新分词生成全文索引，切分 chunk 重新计算 Embedding，并更新各知识点的 `index_status`。
