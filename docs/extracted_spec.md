知识库管理系统

产品功能设计方案 V1.0

定位：个人知识沉淀 × 统一搜索 × AI 搜索回流

| 核心原则：先查自己的知识，再向 AI / 公网提问；有价值的搜索结果由用户确认后沉淀为可持续维护、可检索、可追溯的知识。 |

| 项目 | 说明 |
| 目标用户 | 以个人使用为第一阶段目标，不设计公司、部门、复杂角色权限。 |
| 核心数据来源 | ① AI 搜索记录收藏入库；② 用户手工录入；后续可扩展网页剪藏、文件导入。 |
| 核心能力 | 知识编辑、标签、全文/语义搜索、AI 补充搜索、收藏入库、来源追溯、备份恢复。 |
| 内容形态 | 富文本、表格、图片、附件、代码、画板/白板、流程图等块内容。 |
| 设计目标 | 让“搜索 → 获取答案 → 筛选 → 沉淀 → 再利用”成为一个闭环。 |

1. 项目定位与目标

本系统不是单纯的笔记软件，也不是单纯的 AI Chat/RAG 工具，而是一个面向个人长期使用的“可积累知识搜索系统”。核心价值是减少重复搜索，让用户曾经确认过、有价值的信息逐渐形成自己的知识资产。

1.1 核心目标

统一管理用户主动录入与 AI 搜索收藏形成的知识。

任何问题优先从知识库查找；本地结果不足时，再继续 AI/联网搜索。

AI 搜索结果支持选择性收藏，避免自动生成大量低质量知识。

通过分类、标签、全文检索、语义检索等方式快速定位内容。

支持复杂内容表达，而不仅限于 Markdown 文本。

所有 AI 回答和收藏内容尽可能保留来源，便于验证与追溯。

1.2 暂不纳入第一阶段

企业组织架构、部门、成员管理。

复杂 RBAC 权限、审批流。

多人实时协作与评论体系。

知识付费、公开社区、内容推荐。

复杂 Agent 自动执行任务。

3. 产品核心闭环

1. 用户输入问题或关键词。

2. 系统同时执行标题/正文/分类/标签等关键词检索，以及语义检索。

3. 系统展示“知识库结果”，并判断现有知识是否足够覆盖问题。

4. 结果不足时，提供“继续 AI 搜索”入口；用户可主动点击，也可配置自动触发规则。

5. AI 基于公网搜索/指定搜索服务生成答案，并展示来源。

6. 用户认为答案有价值时点击“收藏到知识库”。

7. AI 一键优化知识内容

针对用户手动添加或编辑的知识内容，在知识编辑器中提供“AI 优化”操作。用户完成初步记录后，可调用 AI 对内容进行纠错、精简和结构化整理，使知识表达更准确、简洁、易理解，同时保持原有事实和核心含义不变。

7.1 优化目标

• 修正错别字、标点、病句和语法问题。• 删除重复、冗余和无效表达，降低阅读成本。• 优化段落、标题、列表和步骤结构，使内容更容易扫描和理解。• 将口语化、零散描述整理为清晰的书面知识表达。• 保留代码、表格、图片、链接、流程图、画板等非普通文本内容及其中的关键数据。

7.2 交互流程

用户录入/编辑知识 → 点击“AI 优化” → AI 生成优化版本 → 展示原文与优化后内容对比 → 用户确认 → 替换原内容。用户可选择“重新优化”或“放弃修改”。建议支持差异高亮，明确展示新增、删除和修改内容，AI 结果不得直接覆盖原文。

7.3 优化模式

MVP 默认提供“简洁易懂”模式。后续可扩展“结构化整理”“专业表达”“仅纠错”等模式。结构化整理重点调整标题、章节、列表和步骤；专业表达提升术语和书面表达规范性；仅纠错只处理错别字、标点和语法，不主动改变内容结构。

7.4 AI 内容安全约束

AI 优化属于“改写已有知识”，不得把模型自身知识作为事实补充进知识点，不得擅自修改代码、数字、URL、产品名、专有名词和技术结论。若原文存在事实矛盾、信息缺失或明显歧义，应提示用户确认，而不是自行猜测或补全。

7.5 分类与标签联动

优化完成后，AI 可基于优化后的正文推荐知识分类和标签。优先从已有分类和标签中匹配，例如“技术类”“公司知识类”；推荐结果必须由用户确认后保存，不自动创建大量新标签。

7.6 优化记录

建议保存最近一次 AI 优化的时间、使用模式及确认状态；如后续启用版本历史，可将优化前内容作为一个历史版本保存，以支持回溯。MVP 至少应保证用户确认前原文不丢失。

7. 系统将搜索问题、AI 答案、来源、分类建议、标签建议等生成知识草稿。

8. 用户确认/编辑后正式入库，并建立检索索引。

9. 未来再次查询相同或相近问题时，优先命中已沉淀知识。

| 关键设计：AI 搜索结果默认只是“搜索记录”，不是正式知识。只有用户主动收藏/确认后才进入知识库，防止知识库被低质量或重复 AI 内容污染。 |

5. 知识点模型

系统中的最小业务对象称为“知识点（Knowledge Item）”。一个知识点可以是一条简短结论，也可以是一篇包含多个内容块的长文。

| 字段 | 说明 | 要求 |
| 标题 | 知识点名称 | 必填；支持 AI 从正文生成 |
| 摘要 | 快速理解内容 | 可手工填写或 AI 生成 |
| 正文 blocks | 结构化内容块 JSON | 必填 |
| 纯文本索引 text | 由 blocks 派生 | 用于全文检索/Embedding |
| 标签 tags | 多标签 | 支持手工与 AI 建议 |
| 来源类型 | manual / ai_search / import / web_clip | 必填 |
| 来源信息 | URL、搜索问题、AI provider、引用等 | AI 收藏时自动保留 |
| 状态 | draft / published / archived / trashed | 支持草稿与回收站 |
| 收藏/置顶 | 快速访问属性 | 可选 |
| 创建/更新时间 | 审计字段 | 自动 |
| 版本号 | 内容历史 | 修改时生成版本 |
| 索引状态 | pending / indexed / failed | 便于诊断搜索索引 |
| 分类 category | 知识主要归属 | 原则上单选；默认技术类/公司知识类；支持子分类 |

6. 知识编辑器

建议采用 Block Editor，而不是把所有内容保存成一段 HTML。每个块具有独立 ID、类型和属性，既方便复杂编辑，也便于未来按块检索、引用和 AI 操作。

6.1 V1 内容块

| 块类型 | 能力 |
| Paragraph / Heading | 普通文本、H1-H4、粗体、斜体、颜色、链接、行内代码。 |
| List / Todo | 有序、无序、待办列表。 |
| Quote / Callout | 引用、提示信息。 |
| Code | 语言选择、语法高亮、复制。 |
| Table | 增删行列、合并单元格、对齐、基础格式。 |
| Image | 上传、粘贴、拖入、标题/说明、缩放。 |
| Attachment | 文件上传与下载；记录文件元数据。 |
| Divider | 内容分隔。 |
| Mermaid | 流程图、时序图、类图等文本式图表。 |
| Canvas / Whiteboard | 自由画板；文字、便签、形状、箭头、图片、连接线。 |
| Embed | 网页/视频等外部内容嵌入，可后续实现。 |

6.2 编辑体验

输入“/”呼出块命令。

块可拖动排序、复制、删除、转换类型。

自动保存草稿，避免页面关闭丢失。

粘贴 Markdown / HTML 时尽量转换为结构化块。

图片粘贴后自动上传对象存储。

流程图优先采用 Mermaid，画板用于自由表达；两者分别保存。

提供“AI 整理”能力：总结、润色、生成标题/摘要、提取标签，但修改需用户确认。

8. 分类管理

7.1 分类定位

分类用于确定知识的主要归属，标签用于描述知识的多个横向属性。一个知识点原则上归属一个主分类，同时可绑定多个标签。分类应保持稳定、数量可控；标签则允许更灵活地扩展。

7.2 默认分类

系统初始化预置两个顶级分类：① 技术类；② 公司知识类。用户后续可按需要增加分类或子分类，例如“技术类 / Shopify”“技术类 / 基础设施”“公司知识类 / 业务规则”“公司知识类 / 流程规范”。

7.3 分类管理能力

支持新增、编辑分类名称与说明，并可设置图标/颜色作为视觉辅助。

支持一级分类和子分类，MVP 建议最多 2～3 层，避免层级过深。

支持拖动或指定排序，知识库侧边栏按分类顺序展示。

支持分类重命名；重命名不影响分类下已有知识。

删除分类前必须处理已有知识：迁移到其他分类、设为“未分类”或取消删除。

支持停用分类。停用后不可用于新知识，但历史知识仍可查看和迁移。

分类管理页展示每个分类的知识数量、子分类数量和最近更新时间。

新建知识和 AI 搜索收藏入库时均可选择分类；AI 可推荐分类，但最终由用户确认。

7.4 分类搜索与过滤

知识列表和统一搜索均支持按分类过滤；选择父分类时默认包含其全部子分类。分类过滤可与标签、来源、时间等条件组合，例如：分类=技术类，标签=Shopify + CDN。

8. 标签体系

8.1 标签能力

一个知识点可绑定多个标签。

支持在编辑页快速创建标签。

标签支持名称、颜色（可选）、说明、父标签/分组。

标签管理页显示知识数量、最近使用时间。

支持标签重命名、合并；合并时自动迁移知识关系。

支持 AI 推荐标签，但不自动创建大量新标签；优先匹配已有标签。

8.2 搜索过滤

统一搜索结果可按标签、来源类型、更新时间、是否收藏、内容类型过滤。例如：“Shopify + CDN”两个标签，来源=AI 搜索，更新时间=最近 30 天。

9. 搜索系统设计

9.1 统一搜索框

首页顶部和全局导航均提供同一个搜索入口。用户不需要先判断应该“搜知识库”还是“问 AI”。系统先使用已有知识，结果不足时再向外部搜索扩展。

9.2 本地检索策略

1. Query 预处理：分词、拼写/同义词处理（可选）、生成 query embedding。

2. 结构化过滤：先应用标签、时间、来源等过滤条件。

3. 关键词召回：标题权重最高，其次标签、摘要、正文。

4. 语义召回：从知识/内容块向量中寻找语义相似结果。

5. 融合排序：关键词分数 + 语义分数 + 标题命中 + 更新时间/收藏等业务权重。

6. 结果去重：同一知识多个 chunk 命中时聚合到知识级展示，并高亮最佳片段。

8.3 搜索结果页

顶部保留查询词，可继续修改。

“知识库结果”区域展示标题、摘要/命中片段、标签、来源、更新时间、相关度。

左侧/顶部过滤器：标签、来源、时间。

结果可直接预览，也可打开完整知识。

当结果不足时，在结果末尾出现明显的“继续使用 AI 搜索”操作。

8.4 “未查询到”判定

不建议只用“结果数量=0”判断。应配置最低相关度阈值和有效结果数量，例如 Top 5 中最高融合分低于阈值，或没有任何结果满足 minimum_score，则视为本地知识不足。阈值需要通过实际数据调优。

10. AI 搜索

9.1 搜索模式

| 模式 | 行为 |
| 知识优先（默认） | 先检索本地知识；足够时基于知识回答并引用知识点。 |
| 补充搜索 | 本地不足时调用公网 AI Search，并同时把本地命中作为上下文。 |
| 仅知识库 | 禁止联网，只允许根据已有知识回答。 |
| 直接 AI 搜索 | 用户明确选择时跳过本地充分性判断，但仍可展示相关本地知识。 |

9.2 AI 搜索结果结构

直接答案/总结。

引用来源列表：标题、URL、站点、抓取/访问时间。

“已有知识”引用：明确区分内部知识和公网来源。

建议标签。

相关问题建议（可选）。

操作：收藏到知识库、复制、重新搜索、打开来源。

9.3 收藏入库流程

1. 点击“收藏到知识库”。

2. 弹出入库预览：标题、摘要、正文、标签、来源。

3. 系统自动把 AI 回答转成编辑器 blocks；引用转换为 Source Block/参考资料区。

4. 检测相似知识：如存在高相似内容，提示“更新已有知识 / 仍新建”。

5. 用户确认后保存。

6. 异步生成全文索引、Embedding；成功后立即可被后续搜索命中。

11. 知识详情与维护

阅读模式与编辑模式分离，减少误操作。

展示标签、来源、创建时间、更新时间。

AI 搜索收藏的知识必须可查看“原始搜索问题”和“原始来源”。

提供关联知识：根据标签 + 向量相似度推荐。

支持复制知识链接；后期可支持 [[知识引用]] 和反向链接。

编辑自动产生历史版本；用户可查看差异并恢复。

删除先进入回收站，定期/手工彻底删除。

12. 搜索记录与知识沉淀

AI 搜索记录与正式知识必须分表/分对象管理。搜索记录是过程数据，知识是用户确认后的资产。

| 搜索记录字段 | 用途 |
| query | 用户原始问题 |
| local_hits | 当时命中的知识及分数快照 |
| search_mode | 知识优先/联网等 |
| ai_answer | AI 生成答案 |
| citations | 公网引用来源 |
| model/provider | 使用的模型和搜索服务 |
| created_at | 搜索时间 |
| saved_knowledge_id | 若收藏，关联生成的知识点 |

13. 首页 / 知识工作台

主搜索框：页面视觉中心，提示“搜索你的知识；找不到再问 AI”。

快捷新建：知识、画板、流程图。

最近访问 / 最近编辑。

待整理：已收藏但仍为草稿的 AI 搜索内容。

分类导航与常用标签。

最近 AI 搜索。

简单统计：知识总数、分类数、标签数、本月新增、AI 收藏数量。

14. 数据安全、导出与备份

知识元数据与正文存数据库；图片/附件使用对象存储或本地文件存储。

支持一键导出完整备份包：数据库数据 + assets + manifest/version。

支持从完整备份包恢复，并在恢复前校验版本与完整性。

知识支持单篇导出 Markdown/HTML；复杂 Canvas 可附带 JSON/PNG。

定时备份作为第二阶段能力：保留最近 N 份，并显示最近成功时间。

删除知识时同步处理搜索索引/向量，但附件采用延迟清理，避免误删共享资源。

15. 推荐技术架构

第一阶段建议采用模块化单体，而不是一开始拆微服务。AI/RAG 与异步索引作为独立 Worker 即可。

| 层 | 建议 |
| Web 前端 | Next.js / React + TypeScript。 |
| 块编辑器 | 优先评估 BlockSuite、Tiptap/ProseMirror；画板可评估 Excalidraw 或 BlockSuite Canvas。 |
| 流程图 | Mermaid。 |
| 后端 API | NestJS（若团队偏 TS）或 FastAPI（若 AI/Python 能力更多）；二选一统一即可。 |
| 业务数据库 | PostgreSQL。 |
| 全文检索 | MVP 可 PostgreSQL FTS；数据量/检索要求上升后使用 Elasticsearch/OpenSearch。 |
| 向量检索 | MVP 推荐 pgvector，减少组件数量；后期可切 Qdrant/Milvus。 |
| 对象存储 | S3 兼容存储（MinIO/云对象存储）。 |
| 异步任务 | Redis + BullMQ / Celery，用于 embedding、摘要、导入等。 |
| LLM 接入层 | 统一 Provider Adapter，支持 OpenAI-compatible API，避免绑定单模型。 |
| Web/AI Search | 封装 Search Provider；允许接入具备联网搜索能力的模型或独立搜索 API。 |

| 架构原则：知识正文的“权威数据”应保存在业务数据库；全文索引与向量索引均属于可重建的派生数据。这样即使搜索引擎或向量库损坏，也可以从知识正文重新构建。 |

17. 关键业务规则

1. AI 搜索结果不会自动成为知识。

2. 知识删除后必须从可搜索索引中移除。

3. 修改知识后，受影响的 chunk 必须重新 Embedding；未修改块尽量复用。

4. 标签 AI 推荐优先从已有标签中选择，只有明确必要时才建议新标签。

5. AI 回答引用内部知识时，必须能跳转到具体知识点，最好定位到命中块。

6. 公网 AI 搜索收藏后必须保留原始 URL/引用；来源失效也不能丢掉当时记录。

7. 所有自动生成标题、摘要、标签都是辅助信息，用户可修改。

8. 画板/流程图既保存可编辑源数据，也生成用于预览/搜索的文本描述或缩略图。

21. MVP 验收标准

用户可以创建包含文本、标题、列表、代码、表格和图片的知识，并稳定自动保存。

用户可为知识选择主分类、添加多个标签，并按分类或一个/多个标签过滤。

输入关键词后可以同时召回标题/正文/分类/标签命中结果。

输入自然语言问题，可以召回语义相近但不包含完全相同关键词的知识。

本地知识不足时，可以继续 AI 搜索，且答案展示来源。

AI 搜索结果可以一键进入“入库预览”，确认后成为知识。

新收藏知识完成索引后，可被下一次相似查询命中。

AI 收藏知识可以追溯原始 query、AI 回答来源和收藏时间。

支持导出完整备份并在空环境恢复主要知识、标签和资源引用。

索引损坏/清空后可以从业务数据库重新构建全文和向量索引。

21. 建议的第一阶段开发顺序

1. 建立数据模型：Knowledge / Category / Tag / Source / SearchSession / Asset。

2. 完成基础块编辑器、知识 CRUD 和 AI 一键优化（预览确认后应用）。

3. 完成分类管理、标签管理与知识列表过滤。

4. 完成全文检索。

5. 接入 Embedding + pgvector，完成混合检索。

6. 实现统一搜索结果页和“本地知识不足”判断。

7. 接入 AI Search Provider，完成联网回答和引用。

8. 实现 AI 搜索收藏 → 入库预览 → 知识索引闭环。

9. 补齐图片/附件、Mermaid；画板可放在 MVP 后半段。

10. 实现导出备份、恢复、索引重建。

11. 最后做版本历史、相似知识、AI 标签等增强功能。

21. 结论

该系统最重要的不是“再做一个 Notion”，而是建立一个个人知识获取与复用闭环：用户每一次有价值的 AI 搜索都可以转化为自己的知识资产；下一次遇到相同问题时，系统优先利用已经确认过的知识，并在不足时再调用外部 AI。编辑器负责承载复杂知识，标签和混合检索负责找到知识，AI Search 负责补充未知知识，收藏入库负责让系统越用越有价值。
